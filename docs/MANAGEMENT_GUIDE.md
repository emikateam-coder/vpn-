## 1. Оценка безопасности текущей настройки

### Что сделано [OK]

| Компонент | Статус | Описание |
|-----------|--------|----------|
| VLESS-Reality | [OK] | Протокол, устойчивый к обнаружению DPI/ТСПУ |
| XTLS-Vision | [OK] | Защита от детектирования TLS-inside-TLS |
| uTLS (chrome) | [OK] | Маскировка TLS-отпечатка под Chrome |
| Панель на localhost | [OK] | 3X-UI слушает только 127.0.0.1 (недоступна извне) |
| Случайный порт панели | [OK] | Порт панели рандомизирован (не стандартный 2053) |
| Скрытый URL панели | [OK] | Панель доступна по секретному пути, а не по / |
| Случайные логин/пароль панели | [OK] | Не admin/admin |
| BBR | [OK] | TCP BBR включён (ускорение соединений) |
| Блокировка торрентов | [OK] | BitTorrent заблокирован на сервере |

### Что НЕ сделано [RISK]

| Компонент | Риск | Рекомендация |
|-----------|------|-------------|
| SSH пароль простой | [HIGH] | Сменить на SSH-ключи, отключить вход по паролю |
| SSH порт 22 | [MEDIUM] | Сменить на нестандартный (например 51822) |
| root доступ по SSH | [MEDIUM] | Создать обычного пользователя, отключить root |
| fail2ban не установлен | [MEDIUM] | Установить для защиты от брутфорса |
| Firewall отключён | [MEDIUM] | Включить UFW, открыть только нужные порты |
| Автообновления не настроены | [LOW] | Включить unattended-upgrades |
| Нет отдельного пользователя | [LOW] | Создать пользователя без root |

### Итоговая оценка

Протокол VLESS-Reality -- один из самых защищённых на данный момент. Его не умеют обнаруживать ни в РФ, ни в Китае. Однако сам сервер уязвим к взлому через SSH (простой пароль, стандартный порт, root-доступ). Выполнение рекомендаций из раздела 5 закроет эти уязвимости.

## 2. Доступ к панели 3X-UI

Панель привязана к localhost -- доступна только через SSH-туннель.

### Подключение

```bash
ssh -L 22222:127.0.0.1:29887 root@77.110.108.137 -p 22
```

После этого откройте в браузере:

```
http://127.0.0.1:22222/d47a3bb3977b4a1e/
```

### Учётные данные

```
Логин: 9aa6f7cf74aa
Пароль: pl1Y13Un2Ua0TD04s8YD
```

### Смена логина/пароля панели

1. Войдите в панель
2. Перейдите в **Panel Settings** (значок шестерёнки слева)
3. Вкладка **User Setting** (или **Security**)
4. Введите старые и новые логин/пароль
5. Нажмите **Save**
6. Нажмите **Restart Panel**

## 3. Управление пользователями

### Добавление нового пользователя

1. Откройте панель через SSH-туннель (раздел 2)
2. Перейдите в **Inbounds** (левое меню)
3. Найдите строку **VLESS-Reality** и нажмите **+** (Add Client)
4. Заполните:
   - **Email** -- имя клиента (например: `client_WorkPC`)
   - **UUID** -- оставьте автосгенерированный или нажмите кнопку генерации
   - **Flow** -- ОБЯЗАТЕЛЬНО выберите `xtls-rprx-vision`
   - **Limit IP** -- 0 (без лимита) или число одновременных подключений
   - **Total GB** -- 0 (безлимит) или лимит трафика в ГБ
   - **Expiry Time** -- 0 (бессрочно) или дата истечения
5. Нажмите **Submit**
6. Для получения ссылки: нажмите на иконку QR/ссылки у нового клиента

### Удаление пользователя

1. В списке клиентов найдите нужного
2. Нажмите иконку корзины рядом с клиентом
3. Подтвердите удаление

### Отключение пользователя (без удаления)

1. Найдите клиента в списке
2. Нажмите на переключатель **Enable** чтобы деактивировать
3. Клиент больше не сможет подключаться, но его UUID сохранится

### Просмотр статистики

- В разделе **Inbounds** видно общий трафик
- Нажмите на стрелку раскрытия у VLESS-Reality
- Для каждого клиента видно: Upload, Download, общий трафик

### Установка лимитов

При редактировании клиента доступны:
- **Total GB** -- лимит общего трафика (upload + download)
- **Expiry Time** -- срок действия подключения
- **Limit IP** -- максимум одновременных подключений (0 = без лимита)

## 4. Настройка клиентских приложений

### Рекомендуемые приложения

| Платформа | Приложение | Ссылка |
|-----------|-----------|--------|
| Windows/Linux/Mac | Nekoray | github.com/MatsuriDayo/nekoray |
| Windows | V2RayN | github.com/2dust/v2rayN |
| Windows/Linux/Mac | Hiddify | github.com/hiddify/hiddify-app |
| Android | V2RayNG | github.com/2dust/v2rayNG |
| Android | Hiddify | Google Play Store |
| Android | NekoBox | github.com/MatsuriDayo/NekoBoxForAndroid |
| iOS | Streisand | App Store |
| iOS | FoXray | App Store |
| iOS | Shadowrocket | App Store (платное) |

### Импорт конфигурации

1. Скопируйте VLESS URL целиком (от `vless://` до `#VLESS-Reality-...`)
2. В приложении нажмите **+** или **Add from Clipboard**
3. Проверьте что все поля заполнены:
   - Address: `77.110.108.137`
   - Port: `443`
   - UUID: ваш UUID
   - Flow: `xtls-rprx-vision` (КРИТИЧЕСКИ ВАЖНО)
   - Security: Reality
   - SNI: `www.microsoft.com`
   - Fingerprint: chrome
   - Public Key: ваш ключ
   - Short ID: ваш short ID

### Настройка маршрутизации (важно)

Правильная маршрутизация -- ключ к безопасности. Настройте так:

**Через прокси (proxy):**
- Весь заблокированный контент (YouTube, Discord, ChatGPT и т.д.)
- Зарубежные сайты, к которым нужен доступ

**Напрямую (direct) -- НЕ через прокси:**
- Все российские сайты (.ru, .su, .by)
- Yandex, VK, Mail.ru, Госуслуги
- Российские IP-адреса (geoip:ru)
- Локальная сеть (geoip:private)

**Заблокировать (block):**
- Рекламные домены (по желанию)

**Почему это важно:** если РКН увидит, что пакет ушёл за границу и вернулся обратно к российскому сайту, это признак прокси. Сервер может быть заблокирован.

### Режим работы клиента

- **TUN/VPN режим** -- рекомендуется, перехватывает весь трафик системы
- **System Proxy** -- проще, но некоторые приложения могут его игнорировать

## 5. Рекомендации по усилению безопасности

### 5.1. Смена SSH-пароля и переход на ключи

```bash
# На вашем ПК сгенерируйте ключ
ssh-keygen -t ed25519 -C "my-vps-key"

# Скопируйте на сервер
ssh-copy-id -p 22 root@77.110.108.137

# Проверьте вход по ключу (без пароля)
ssh -p 22 root@77.110.108.137

# На сервере отключите вход по паролю
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart sshd
```

### 5.2. Смена SSH-порта

```bash
# На сервере
sed -i 's/^#*Port .*/Port 51822/' /etc/ssh/sshd_config
systemctl restart sshd
```

После этого подключайтесь с `-p 51822`:

```bash
ssh -p 51822 root@77.110.108.137
ssh -L 22222:127.0.0.1:29887 root@77.110.108.137 -p 51822
```

### 5.3. Установка fail2ban

```bash
apt install -y fail2ban
systemctl enable --now fail2ban
```

Это автоматически блокирует IP-адреса после нескольких неудачных попыток входа.

### 5.4. Настройка firewall (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 51822/tcp    # SSH (ваш новый порт)
ufw allow 443/tcp      # VLESS-Reality
ufw enable
```

### 5.5. Автоматические обновления безопасности

```bash
apt install -y unattended-upgrades
dpkg-reconfigure -plow unattended-upgrades
```

### 5.6. Создание обычного пользователя (опционально)

```bash
adduser vpnadmin
usermod -aG sudo vpnadmin

# Отключить root SSH
sed -i 's/^#*PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
systemctl restart sshd
```

## 6. Обслуживание сервера

### Перезапуск сервисов

```bash
# Перезапуск 3X-UI + Xray
systemctl restart x-ui

# Только Xray (через панель API или из панели)
# В панели: Dashboard -> Restart Xray

# Перезагрузка сервера
reboot
```

### Обновление 3X-UI

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

### Обновление системы

```bash
apt update && apt upgrade -y
```

### Резервное копирование

Скачайте базу данных панели:

```bash
# Через SSH
scp -P 22 root@77.110.108.137:/etc/x-ui/x-ui.db ./x-ui-backup.db
```

Или через панель: **Panel Settings** -> **Backup** -> **Export**

### Мониторинг

```bash
# Статус сервиса
systemctl status x-ui

# Логи Xray
journalctl -u x-ui -f

# Использование ресурсов
htop

# Сетевые подключения
ss -tlnp
```

### Смена домена маскировки

Если текущий домен перестал работать:

1. Откройте панель
2. **Inbounds** -> **VLESS-Reality** -> **Edit**
3. Вкладка **Stream Settings** -> **Reality**
4. Измените **Dest** на новый домен (например `www.google.com:443`)
5. Измените **Server Names** на тот же домен
6. Нажмите **Save**
7. Раздайте клиентам НОВЫЕ ссылки (в них изменится SNI)

Хорошие домены для маскировки:
- `www.microsoft.com`
- `www.google.com`
- `www.cloudflare.com`
- `www.samsung.com`
- `www.whatsapp.com`
- `gateway.icloud.com`

Требования к домену: TLS 1.3, H2, не блокирует по GeoIP, стабильный.

## 7. Устранение неполадок

### Клиент подключается, но сайты не грузятся

1. Проверьте **Flow** в настройках клиента -- должен быть `xtls-rprx-vision`
2. Проверьте **SNI** -- должен совпадать с доменом маскировки на сервере
3. Попробуйте сменить домен маскировки (раздел 6)
4. Попробуйте другое клиентское приложение

### Клиент не подключается вообще

```bash
# Проверьте что Xray слушает порт 443
ssh root@77.110.108.137 "ss -tlnp | grep 443"

# Проверьте статус x-ui
ssh root@77.110.108.137 "systemctl status x-ui"

# Перезапустите
ssh root@77.110.108.137 "systemctl restart x-ui"
```

### Панель 3X-UI не открывается

```bash
# Проверьте на каком порту слушает панель
ssh root@77.110.108.137 "ss -tlnp | grep x-ui"

# Используйте порт из вывода для SSH-туннеля
ssh -L 22222:127.0.0.1:<ПОРТ> root@77.110.108.137
```

### Медленная скорость

1. Проверьте BBR: `sysctl net.ipv4.tcp_congestion_control` (должен быть bbr)
2. Проверьте нагрузку: `htop`
3. Возможно, провайдер ограничивает скорость -- попробуйте другой порт

### Забыли пароль от панели

```bash
# На сервере через SSH
sqlite3 /etc/x-ui/x-ui.db "SELECT username FROM users;"
# Сбросить пароль на admin
x-ui setting -username admin -password admin
systemctl restart x-ui
```

## 8. Что делать если сервер заблокировали

1. **Не паникуйте** -- VLESS-Reality крайне сложно обнаружить
2. Проверьте, доступен ли сервер по SSH:
   ```bash
   ssh -p 22 root@77.110.108.137
   ```
3. Если SSH работает, а VPN нет -- проблема в Xray, перезапустите:
   ```bash
   systemctl restart x-ui
   ```
4. Если SSH не работает -- сервер мог быть заблокирован. Варианты:
   - Подождите 1-2 часа (иногда блокировки временные)
   - Зайдите через веб-консоль хостера (Aeza/panel)
   - Арендуйте новый сервер у другого провайдера
5. Превентивные меры:
   - Не используйте WireGuard/OpenVPN на том же IP (отравляют адрес)
   - Не отправляйте российский трафик через прокси
   - Используйте правильную маршрутизацию на клиенте
